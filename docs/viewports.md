# Four-view workspace

**Four views**, in the viewer header, opens Top, Front, Right, and Perspective panels. Hover a panel to direct navigation and tools to its camera. **Space** over the canvas maximizes that panel; Space again restores the split. In the initial single view, Space opens the split. Text fields retain normal typing. Each panel has the native world-axis widget; its direction buttons change only that camera. Clicking the panel label restores perspective projection. Q exits the current tool without changing the layout.

The layout belongs to the viewer, including selection, measurement, annotation, Views, and Sectioning. One asset orientation, clipping plane, selection/paint history, measurement document, and annotation document are shared across panels. Changing a panel direction never changes the section. Saved Views capture the asset orientation and active camera, rather than duplicating the four-panel document. Saved sections capture the reference, adjustments, retained side, asset orientation, and active camera; recall restores that snapshot. Views and Sections appear in the model tree with existing selections, measurements, and annotations. Section visibility enables/disables the single active cut; saved sections are alternatives, not simultaneous intersecting cuts. Renaming does not restore a snapshot. Records last until leaving/refreshing the asset; browser persistence remains deferred.

## Engine boundaries and cost

One PlayCanvas application, canvas, model, and scene use native cameras with `rect` and `scissorRect`. Three inspection cameras are created only when first opening the split and retained for later toggles. Maximizing disables the other cameras. Only the active camera's native navigation script accepts input. Native cameras retain their own orbit target, zoom, and projection. Visible cameras each require rendering/culling and, for splats, native sorting resources; four views cost more than one even though their combined pixel area is similar. Source geometry and selection/paint buffers are shared.

Pointer mapping and selection masks use the active panel's rectangle. Native Picker/RenderPassPicker retain GPU depth and ID picking. In pinned PlayCanvas 2.21.4, Picker unprojects full-target coordinates, while unified splats retain state keyed by the original camera. `renderPickView` therefore temporarily uses a full rectangle and fixed aspect on that same camera for the synchronous panel-sized pick pass, then restores every setting before readback or scene rendering. It allocates no camera, sorts no extra view, and restores state even on errors. Review this small adapter on engine upgrades.

Camera-facing measurement and annotation visuals have one instance per visible camera, with shared underlying records. Measurement renderers share the font atlas and material. Native annotation managers own only their panel's visual entities; a pinned adapter adjusts projection and billboard sizes for the camera rectangle and orthographic projection. Hover uses one shared GPU query, not a query for every panel. Native axis widgets update only when their camera matrix changes. All extra cameras, visual layers, and callbacks are released on teardown.

## XR

Desktop inspection cameras must not replace headset eye projections. The workspace collapses to the session's native camera on XR start, disables the other cameras, and restores the desktop layout on session end. Scene tool operations remain shared. This lifecycle adapter is not a complete XR implementation: immersive entry, controller/hand bindings, browser-panel/annotation-tooltip presentation, and actual headset validation remain tracked in TODO. Browser stereo checks do not establish immersive-session compatibility.

## Verification

Follow [browser verification](browser-verification.md). Include actual pointer gestures in all four panels, Space maximize/restore, native axis navigation, view creation/recall, sectioning and surface measurements, painting and bound annotations, marker dragging, undo/redo, and navigation away. Use a known-size engine fixture to check coordinate conversion numerically, in addition to representative real assets. Repeat critical workflows against the minified production build. Do not treat a changed camera matrix alone as a rendering test.

The October 2026 checks exercised both development and minified production builds with a real mesh and SOG splat: saved view → section → measurement, selection → paint → bound annotation, marker dragging, independent navigation, native gizmo rotation, undo/redo, tree rename/recall, retina resize/fullscreen, and teardown. An engine-generated cube checked a one-unit span in Top/Front/Right and after a cut (pixel-quantized results within 0.01 units). Larger mesh and 1.5-million-splat smoke checks verified four rendered cameras and one after maximizing. These are local Chromium/WebGL results, not a cross-device performance guarantee or headset test.
