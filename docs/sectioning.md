# Cross sections

The shared **Cross section** tool clips meshes and splats with one world-space plane. Choose **From current camera** or load a named view (restoring its asset orientation and camera), then choose its viewing normal or world X/Y/Z; enable the section, slide Offset, adjust Tilt 1/2, or Flip the retained side. **Look perpendicular to cut** places the camera on the removed side looking into the retained geometry, accounting for Flip and preserving the plane's up direction and orbit pivot. The optional translucent cutting plane is scene geometry. Q exits the tool and removes its guide while leaving clipping enabled; reopen the tool to disable it. Source geometry remains unchanged. **Section name → Save section** stores the current cut in the saved box above the options and in the model tree. Click the saved-box entry to restore/edit it; **Update section** replaces it, and the minus button deletes it. The model tree only lists records, renames them, and toggles the active cut. Tree eye controls do not restore the camera or open an editor. Views and section settings are session-local; persistent storage is deferred. The viewer-wide [four-view workspace](viewports.md) shows the same cut from each panel and supports measurement/selection there.

## Shared geometry and controls

`ViewFrame` supplies an origin and quaternion. Local X/Y span the reference plane and +Z is its normal. Offset is a percentage of a span derived from the engine's asset bounding box, so its limits sweep beyond the asset even for a tilted or translated reference. Tilts rotate around the reference axes; flip negates the plane coefficients without moving the plane. PlayCanvas `Plane.setFromPointNormal`, `Quat`, `Mat4`, and `BoundingBox` supply the math. Complete-object bounds reuse engine bounding boxes; they do not scan all triangles or splats. A selected region still requires its own bounds calculation.

World X/Y/Z cutting-plane alignment belongs to Sectioning, independently of the asset rotation established in Views. The reference dropdown offers only saved views and retains the selected name. **From current camera** is the sole camera-capture action; after capture the dropdown displays a non-selectable Current camera label (and is disabled when there are no saved views). Each offset/tilt slider has an accessible revert icon that resets only its own value. The reference frame is copied at load time. Choosing another axis resets offset and tilts, while Flip only changes the retained side. The section actions are grouped below the alignment/offset/tilt controls.

Views supports three-point asset alignment on both formats. The first point defines the origin, the second the local X direction, and the third the plane orientation. The normal is oriented toward the current view so click winding does not unexpectedly send the camera behind the object. All three use the existing PlayCanvas depth picker; native wire spheres/lines show picked points. Repeated or collinear points are rejected with a scale-independent test. The computation runs once after the third click and uses native vector, matrix, and quaternion operations. There is no face-specific path: Gaussian splats do not have triangle faces.

## GPU rendering and picking

Mesh base materials are cloned once to keep asset resources unchanged. PlayCanvas's `StandardMaterial` user-declaration/main-start shader hooks apply the plane in forward, depth, shadow, and picker passes. Selected and painted material clones retain the same hooks; hover-preview and triangle-ID materials use the same plane. While clipping is enabled, native two-sided rendering and matching picker culling expose reverse surfaces of scanned shells for measurement and annotation. A forward-pass material hook renders unpainted reverse faces in neutral grey without the exterior texture, with lightweight shading from engine-provided normals/view direction. Explicit selection colors and hover previews remain visible on those surfaces. This is a reverse-shell display, not a solid cap or evidence of interior structure; splats have no triangle backface equivalent. Disabling clipping restores the original material settings. These state changes occur only when sectioning is enabled or disabled, not on each slider update.

The [official PlayCanvas clipping example](https://github.com/playcanvas/engine/blob/main/examples/src/examples/gaussian-splatting/clipping.example.mjs) demonstrates shader-based footprint clipping. Our single plane needs only one interpolated signed distance. Splat vertices compute it using the engine's current camera matrices; the fragment stage discards the removed portion of each footprint. This leaves the existing selection/color work-buffer modifier intact. It performs no per-fragment inverse-matrix reconstruction and does not hide whole splats based only on their centers.

The installed 2.23.3 splat fragment-modifier callback runs only in the forward pass. To make clipping agree with depth/ID picking, the existing pinned splat-picking adapter composes a plane-distance varying into `gsplatVS` and an early discard into `gsplatPS`, for GLSL and WGSL. It modifies the native shader entry points rather than replacing the rendering pipeline. Review those insertion points and shader variants on engine upgrades. Previous chunk overrides are restored on disposal.

Plane changes update GPU uniforms and invalidate cached pick images. They do not rebuild model geometry, upload selection/paint masks, or rerun SOG processing. X-ray selection keeps its existing centroid policy, with a local-space plane test prepared once per gesture. Visible-only selection and surface picks use clipped GPU render passes. Tiny-triangle coverage limitations remain the separate selection-accuracy task.

The optional guide reuses one native plane primitive, material, and layer while controls change. Its resources and clipping-uniform ownership are released before graphics-device destruction, including when navigating away. No additional camera or model render pass is introduced for clipping.

## WebXR direction and verification

The plane is world-space, its guide is native scene geometry, and splat clipping uses PlayCanvas's per-camera matrices rather than a cached desktop-camera inverse. These choices support stereo rendering and future shared XR operations. Browser panels, pointer-driven gizmo bindings, XR controllers/hands, AR placement, and immersive session integration are still separate work; engine use alone does not establish headset compatibility.

Production-build browser tests on a real mesh and splat cover named oriented views, section-axis and three-point asset alignment, offset limits, both tilts, flip, guide visibility, camera alignment, Q/navigation, mobile layout, measurement and annotation picks on retained versus removed surfaces, selection colors/isolation/X-ray, and teardown. An engine-generated cube fixture verifies a known span on the newly exposed reverse surface, then selects, paints, and binds an annotation to that surface. A separate native dual-camera check verifies the same world-plane side in both viewpoints. Existing annotation save/focus/marker-drag regressions also pass. These are Chromium/WebGL and two-camera checks, not Safari, WebGPU, or headset certification.

Filled caps and intersection contours remain deferred. A clipping shader cannot establish a solid interior for a scanned shell or Gaussian splat. Evaluate hardened geometry libraries and define the heritage-accuracy requirements before implementing caps; do not substitute an ad hoc triangulator.
