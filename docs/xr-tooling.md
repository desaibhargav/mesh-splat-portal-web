# XR tool integration

Immersive viewing shares the asset scene, saved documents, and section plane with desktop. The headset toolbar exposes Selection, Measurement, Annotation, Views and Sectioning through a PlayCanvas spatial toolbar, options panel, and controller ray. Segments and Capture still need immersive input and panel controls. All slices should reuse the existing `SelectionController`, `Measurement`, `Annotations`, `SavedPresets`, and segment workspaces; a separate XR document or mesh/splat editor would make edits diverge.

## Shared spatial toolbar and options

AR and VR enter in Navigate, even when Measurement was selected on desktop. A level, softly following icon toolbar uses the same icon paths, labels, selected-state gold, and desktop CSS appearance. Navigate, Select, Measurement, Annotate, Views and Cross section are available, in their desktop order. Selecting Measurement opens its separate options panel; every tool switch discards unsaved edits from the tool being left.

The options panel uses the same measurement records, name field, saved-items box, green Save/Update, line-width and font-size sliders with reset controls, red Clear measurements, and trapezoidal collapse/expand control as desktop. The collapse bar stays anchored at the bottom of the panel. Saved entries open for editing or delete from their own list. A scrollbar keeps a long saved list within the headset view. The toolbar and panel share a world-space anchor. Each has a lower grab bar for controller repositioning, and the frame chord recenters them. Normal head movements leave them still; turns beyond 35° or horizontal movement beyond 35 cm start gentle repositioning. Height stays fixed, pitch/roll are ignored, and controller/UI interaction freezes following. Scene measurements stay attached to the artifact. This follows Meta’s world-space/leashed-panel guidance: https://developers.meta.com/vr/documentation/iwsdk/concepts/spatial-ui/hud/. Input on the name field opens a spatial keyboard; Done closes the keyboard, and Save commits the name. Text entry is the headset input adapter, not a separate document or save workflow.

A right-trigger tap places a surface point, with a small white scene marker preview. Pointing at an open measurement's endpoint and holding the trigger drags that endpoint along the visible surface; release commits through the same `Measurement.moveEndpoint` operation as desktop. Elsewhere, right-trigger dragging pans. Left trigger orbits independently; left thumbstick zooms; grips use native PlayCanvas manipulation. Both triggers together frame the asset and recenter the toolbar and options. Left X undoes; left Y redoes. Right B resets to the initial VR framed pose or AR placement, and another B within three seconds exits immersive mode. Tool choice synchronizes to desktop after XR exit to avoid React panel transitions inside the engine's XR input callback.

## Engine and presentation boundaries

`ToolPanel` shares panel drawing, hover feedback, saved lists, collapse and keyboard presentation across supported tools. `SpatialPanel` uses native PlayCanvas world-space Screen/Element components, Texture, and ElementInput. It installs an XR-only ElementInput manager when the React application has none, and releases it on exit. The pinned engine's `XrInputSource.elementEntity` declaration says Entity, while its ElementInput implementation returns ElementComponent; a single cast isolates that mismatch. No separate UI ray picker or `XrMenu` visibility adapter remains.

The UI texture is drawn with browser canvas fonts and shared vector icons. Colours and font family are read from the actual desktop CSS at construction. Tool definitions and measurement slider definitions are shared. Canvas buffers are reused, textures resize through the engine API when the form grows/collapses, and uploads happen on edits and hover changes, not every frame. Mipmapped minification steadies angled panels without lowering their source resolution. The spatial keyboard is allocated for the session and shown only for text input. Review these adapters on engine upgrades.

Desktop and XR measurement preview/clicks use the same surface-ray adapter. Meshes reuse the existing `three-mesh-bvh` selection worker and its public `raycastFirst`/`raycast` functions, without another BVH or a picking camera. Splats build a lazy `PointsBVH` in a worker over a copy of their resident centers; mask updates transfer only after edits. Segment/isolation masks, transforms, side policy, and the retained section plane accompany ray queries. Splat hits remain estimated surface locations. Preview sampling is movement-driven, suppressed while native UI targeting owns the pointer, with at most one query in flight per controller and at most 20 right-hand and 10 left-hand queries per second. The rays and their small endpoint markers still track the live controllers every frame. No idle readback/render pass runs. Hits convert with the inverse asset transform captured at query time, so movement during worker latency does not misplace the stored anchor.

`SurfacePointMarker` supplies the same live white surface sphere on desktop and XR; the shared MeasurementRenderer supplies endpoints, labels and the stereo line. Measurement style is cached before immersive entry: querying inherited CSS on the immersive canvas produced NaN sphere sizes and label offsets. Desktop mouse pickers/gizmos are suspended in XR while shared scene visuals continue rendering. Measurement layers created during XR reattach after desktop camera restoration.

Browser integration tests drive real IWER controller events and check Navigate entry, icon activation, name entry, saved records, sliders, collapse, endpoint dragging, navigation, section coexistence, desktop sharing, and teardown on meshes and splats. A generated plane with known coordinates checks preview/click correspondence, transformed endpoint/line placement, visible endpoint pixels, and absence of extra scene-camera frames. Screenshots include the stereo result and the form texture. Development and minified production builds both require checks. Actual Quest comfort, text legibility, hit targets, and performance still require headset validation; emulator success does not establish those properties.

## Selection and annotations

Selection uses the same masks, `SelectionHistory`, saved areas, paint palette/hex colors and Isolate operations as desktop. Hold the right trigger and draw a Box or Lasso footprint starting on the asset. A translucent gold volume appears during the stroke; on release its depth handle is ready and the draft selection is committed. Drag the handle along the volume axis to update its depth; the mask is recomputed on release, never on every hand movement. No slider or Apply/Cancel step is added. The volume follows the artifact through navigation. The shared mesh BVH worker tests triangle-volume intersections; the splat point BVH worker tests resident centers. Both respect sectioning, scope and isolation. Interior/occluded primitives in the volume are included. The drawing and handle are transient; Save retains the selected region, while leaving the tool discards unsaved work. The name field proposes Selection 1, Selection 2, and so on, allowing immediate Save; typing replaces that default. Brush uses a shallow translucent disc aligned to the picked surface normal. Its stroke follows surface hits and is queried against the existing spatial index on release. Left-trigger orbit, thumbstick zoom and grip manipulation remain available. Right-trigger dragging away from a volume handle or asset pans. Native query cameras remain disabled; layer membership is scoped to the synchronous brush pick pass and restored before asynchronous readback. WebGL CPU-sorted splats replay the resident headset splat mesh through the native depth pass, without a second sorter or geometry copy. This pinned-engine adapter is needed because native `prepareForPicking` handles GPU sorting only; review it on upgrades.

Annotation uses the same `Annotations` document and selection snapshots. Choose point or selection annotation, hover/click a selection, place the marker, enter Title and Description, and Save. Saved notes reopen for editing/removal; a marker can be dragged after opening it or choosing its saved-row Move action, then saved. Cancel and tool exit discard the draft. The existing PlayCanvas annotation scene markers are initialized before XR, and a native spatial description panel presents the note when its marker/region is targeted; no DOM tooltip is required inside the headset. The description panel renders in its own late layer with a cleared depth buffer so mesh intersections cannot hide it. Painted selections retain their color and scope. Saved records remain available on desktop after exit.

Controller rays end at the nearest asset/UI target. Surface results (including stable primitive IDs) are shared with the white measurement/annotation preview and region hover; mesh queries reuse the existing BVH worker, and splats use their resident-center query. There is at most one background query in flight per controller, movement/transform/edit invalidation drives sampling, and no queries run at idle or while pointing at UI. UI clipping uses the native ElementInput target plane. Panel textures redraw on edits and hover transitions; gold border/glow feedback covers buttons, fields, sliders, keyboard keys and collapse controls. Desktop uses the same gold hover/focus styling without layout movement. Native Screen priority ensures the keyboard receives input above the options behind it.

## Remaining slices

1. **Menu and measurement:** Implemented and browser-tested as described above. Quest device validation remains; the spatial name keyboard and style controls are implemented.
2. **Annotations:** Point/region placement, text entry, Save, reopen, marker move and spatial descriptions are implemented; Quest validation remains.
3. **Selection, paint, and segments:** Volumetric box/lasso, controller-view brush, saved selections, paint and annotation binding are implemented. Entering/creating segment workspaces from XR remains deferred.
4. **Views and sections:** Let controller handles rotate the asset relative to the fixed world axes, then save/recall through the existing view records. Expose cutting-plane normal, offset, tilts, flip, and Save through the same section state. Keep the plane and annotations in the shared scene and section picks on retained surfaces.
5. **Capture and remaining document actions:** Define a dedicated XR spectator capture rather than assuming the desktop canvas contains both eyes in a usable PNG. Expose saved-item open, rename, visibility, delete, undo/redo, isolation, and return-to-asset in the menu. Decide whether four-view remains a desktop layout rather than simulating four windows in a headset.

For each slice, run a real browser session with Meta IWER against development and minified production builds for both asset formats, plus a Quest 3 check for interaction comfort, text legibility, controller hit targets, stereo visuals, and performance. Compose each tool with sectioning, segment workspaces, existing saved records, XR manipulation, and session exit/re-entry. Benchmark render time and memory before adding a continuous controller preview or another pick pass. Emulator success does not establish headset usability.

## Headset browser and splat performance boundaries

The headset's ordinary 2D browser exposes generic pointer events, not XR controller handedness. Box and Lasso accept a held drag or two taps there. Right-trigger pan and left-trigger orbit remain distinct only after entering immersive XR; ordinary browser input cannot reliably assign those roles by hand. No Pan mode button is included.

XR keeps every splat in the published asset. PlayCanvas uses background CPU sorting on WebGL and GPU sorting only when WebGPU is available; this is a plausible performance cost, not a measured diagnosis for the reported Quest lag. The prior XR-only framebuffer scale and fixed foveation settings were removed to restore menu legibility. Controller models use scene lighting, and rays render after the UI layer and stop just before the targeted control. Surface probes are skipped while either controller targets UI and throttled when pointing at the asset. Quest frame-time and energy measurements remain necessary before claiming the splat performance problem is resolved.

Splat XR sessions use PlayCanvas's native radial sorting to avoid full worker sorts caused only by head rotation; the previous setting is restored on exit. The replay and resource measurements, visual tradeoff, and remaining Quest uncertainty are recorded in [the splat performance investigation](splat-performance.md).

The former `?xrGpuSort=1` trial was removed after Quest reported WebGL fallback and a separate local WebGPU check found the splat shader adapter could render blank. The GPU sorter uses `gsplatHybridVS`; our section/hover fragment interface must be validated against that path before enabling it. Browser API availability alone does not establish a working renderer. Keep this as an explicit integration gap rather than presenting the trial as a performance fix.

## Passive page rendering

`ViewerRenderPolicy` uses PlayCanvas's `autoRender`, `renderNextFrame`, `frame:ready` and `frame:request` APIs. Loading, active tools, and XR sessions render continuously. Once a non-immersive Navigate scene is ready and its cameras stop moving, it stops issuing scene draws. Camera damping, projection changes, viewport changes, resize, document edits and asynchronous splat sort completion request fresh frames. Selection/paint, measurements, annotations and section controllers invalidate their own visual changes. Text entry retains the previous pause behavior and flushes the final scene on blur.

The policy checks at most four camera matrices on each engine update; it does not scan geometry or allocate a second asset. Native updates and DOM/controller input continue while the GPU is idle. XR remains continuous for tracked poses and live tool visuals. The browser regression measured 60 draws in 60 idle updates before this change and zero after settling, and verifies visible asset pixels, orbit redraw, damping completion and idle pointer movement. That demonstrates removal of idle draw work, not Quest frame rate during orbit or immersive sessions.

## Views and section handles

Views opens with its saved list and Create view action. Creating or reopening a view attaches native PlayCanvas rotation rings to the artifact, with a reference grid outside the asset orientation transform. The same name, Save/Update, Cancel, three-point alignment and reset operations are available. Six direction controls present the asset from the fixed source-world directions without changing its own orientation. Controller surface hits and the shared `threePointFrame` computation implement three-point alignment; native wire spheres show placed points. Leaving the tool restores an unsaved draft. Saved orientations and camera references use the same `NamedView` records as desktop, including views created before XR entry.

Sectioning uses the shared `SectionDocument`, saved sections, source reference, axis alignment, Flip, plane visibility, From current camera, Look perpendicular to cut, Reset and Save/Update. Its yellow sphere adjusts Offset along the plane normal. Two native rotation rings adjust the same Tilt 1/2 values as desktop, with no XR sliders. A trigger gesture produces one history entry; left X/Y undo/redo the active view or section edits. The plane guide and gizmo draw before UI so they cannot tint or overwrite the toolbar/options. Controller rays stop on the relevant handle. Unused rotation shapes are hidden rather than shown as disabled grey geometry.

The installed RotateGizmo exposes DOM pointer input, not a controller-ray picking entry point. `ControllerRotateGizmo` subclasses its protected ray method, uses its native orbit rotation mode and transform events, and narrowly adapts the engine's handle-triangle picker to a tracked ray. It queries only the small gizmo, reuses scratch math, and performs no asset geometry scan or extra asset picking pass. The source revision and MIT attribution are recorded in the adapter and `/licenses/playcanvas.txt`. Review the adapter on engine upgrades.

`ViewerSpace.rotation` remains local to the asset presentation parent. XR placement/navigation adds an outer transform; it does not leak into saved orientation data. A view capture converts the tracked camera into source coordinates; recalling it presents the equivalent artifact orientation/distance without writing a tracked camera pose. The source section plane is owned by `SectionDocument`; `ImmersiveScene` applies its inverse transpose when the cut or XR presentation changes. Cached object-space bounds avoid full asset scans during rotation. A section edit updates uniforms/picking only when its plane actually changes, and dragging does not redraw panel textures every frame. Saved cuts remain available to measurement, selection and annotation after leaving Sectioning. Every tool switch discards unsaved view/section changes.

XR always uses one stereo view. Desktop four-view cameras are suspended for the session and restored on exit; there is no XR split-layout control. Scene gizmos, guides and input listeners are removed on tool/session exit and route teardown. Run `XR_REFERENCES_ONLY=1 XR_ASSET=<slug>` with the documented IWER setup for controller rotation, three points, view save/cancel, offset/tilt, history, saved cut → measurement, and active-session teardown. Add `XR_STREAMED=1` for splats and `XR_EDITING_AR=1` for floor placement. Repeat development and production on both formats. These browser/controller checks do not certify physical Quest ergonomics or performance.
