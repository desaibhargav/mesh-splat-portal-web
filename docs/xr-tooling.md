# XR tool integration plan

Immersive viewing currently shares the asset scene, saved documents, and section plane with desktop. It does not yet expose desktop HTML tool forms or pointer gestures to a headset. Tool integration should reuse the existing `SelectionController`, `Measurement`, `Annotations`, `SavedPresets`, and segment workspaces. A separate XR document or mesh/splat editor would make edits diverge.

## Input and menu boundary

Use the installed PlayCanvas `XrMenu` script for a world-space tool palette. It already implements controller-ray hover/click, hand poke, menu visibility, text, and `app` action events. Supply a local font asset and map its action events to the same tool commands that desktop buttons call. Keep tool commands and save/cancel semantics independent of DOM events. When the menu is open, suppress orbit/pan and one-hand grabs; the bundled `XrManipulation` already responds to `xr:menu:active`, while our gestures and one-hand adapter need to follow that event. Avoid a permanently head-locked panel covering the artifact. Verify menu reach, readable text, and controller conflict on Quest 3.

XR surface picks should originate from `XrInputSource.getOrigin()` and `getDirection()` and return the same world-space point/primitive data consumed by desktop tools. Reuse PlayCanvas `Picker` and model layers for mesh and splat where possible; evaluate a small, on-demand pick camera aligned with the controller ray before introducing a second geometry raycast implementation. Picking should happen on trigger actions, with one reusable target, no per-frame readback, and cancellation on tool/session/workspace changes. Convert hits through `ViewerSpace.toLocal` before storing them. XR UI hits must take precedence over surface picks. Test mesh, splat, sections, segments, and model manipulation before committing to the approach.

## Vertical slices

1. **Menu and measurement:** Navigate/Measure/Save/Cancel in the world-space menu, two controller-ray surface points, persistent stereo line and label, and Q-equivalent cancellation of an unsaved draft. Reopen and move endpoints after saving. Keep desktop behavior unchanged.
2. **Point annotations:** Reuse the same ray picker and annotation records. Provide marker placement, title and description entry through an XR-appropriate text input path, save/cancel, and stereo title/description display. Do not rely on DOM tooltips inside XR.
3. **Selection, paint, and segments:** Define a controller brush in object/world space with a visible preview and explicit visible-only/X-ray policy. Feed its result into the existing masks, histories, saved selections, color operation, and segment workspace. Saved region binding for annotations follows after region hover/pick works in stereo. Box/lasso need an XR-specific gesture definition; copying a 2D marquee into an eye view would be ambiguous.
4. **Views and sections:** Let controller handles rotate the asset relative to the fixed world axes, then save/recall through the existing view records. Expose cutting-plane normal, offset, tilts, flip, and Save through the same section state. Keep the plane and annotations in the shared scene and section picks on retained surfaces.
5. **Capture and remaining document actions:** Define a dedicated XR spectator capture rather than assuming the desktop canvas contains both eyes in a usable PNG. Expose saved-item open, rename, visibility, delete, undo/redo, isolation, and return-to-asset in the menu. Decide whether four-view remains a desktop layout rather than simulating four windows in a headset.

For each slice, run a real browser session with Meta IWER against development and minified production builds for both asset formats, plus a Quest 3 check for interaction comfort, text legibility, controller hit targets, stereo visuals, and performance. Compose each tool with sectioning, segment workspaces, existing saved records, XR manipulation, and session exit/re-entry. Benchmark render time and memory before adding a continuous controller preview or another pick pass. Emulator success does not establish headset usability.
