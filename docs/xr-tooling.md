# XR tool integration

Immersive viewing shares the asset scene, saved documents, and section plane with desktop. The headset toolbar exposes Selection, Measurement and Annotation through a PlayCanvas spatial toolbar, options panel, and controller ray. Segments, Views, Sectioning and Capture still need immersive input and panel controls. All slices should reuse the existing `SelectionController`, `Measurement`, `Annotations`, `SavedPresets`, and segment workspaces; a separate XR document or mesh/splat editor would make edits diverge.

## Shared spatial toolbar and options

AR and VR enter in Navigate, even when Measurement was selected on desktop. A level, softly following icon toolbar uses the same icon paths, labels, selected-state gold, and desktop CSS appearance. Navigate, Select, Measurement and Annotate are available, in their desktop order. Selecting Measurement opens its separate options panel; selecting Navigate closes it and discards unsaved measurement drafts.

The options panel uses the same measurement records, name field, saved-items box, green Save/Update, line-width and font-size sliders with reset controls, red Clear measurements, and trapezoidal collapse/expand control as desktop. The collapse bar stays anchored at the bottom of the panel. Saved entries open for editing or delete from their own list. A scrollbar keeps a long saved list within the headset view. The toolbar and panel share a world-space anchor. Normal head movements leave it still; turns beyond 35° or horizontal movement beyond 35 cm start gentle repositioning. Height stays fixed, pitch/roll are ignored, and controller/UI interaction freezes following. Scene measurements stay attached to the artifact. This follows Meta’s world-space/leashed-panel guidance: https://developers.meta.com/vr/documentation/iwsdk/concepts/spatial-ui/hud/. Input on the name field opens a spatial keyboard; Done closes the keyboard, and Save commits the name. Text entry is the headset input adapter, not a separate document or save workflow.

A right-trigger tap places a surface point, with a small white scene marker preview. Pointing at an open measurement's endpoint and holding the trigger drags that endpoint along the visible surface; release commits through the same `Measurement.moveEndpoint` operation as desktop. Elsewhere, right-trigger dragging pans. Left trigger orbits independently; left thumbstick zooms; grips use native PlayCanvas manipulation. Left X frames the asset in front of the current head pose. Right B resets to the initial VR framed pose or AR placement, and another B within three seconds exits immersive mode. Tool choice synchronizes to desktop after XR exit to avoid React panel transitions inside the engine's XR input callback.

## Engine and presentation boundaries

`ToolPanel` shares panel drawing, hover feedback, saved lists, collapse and keyboard presentation across supported tools. `SpatialPanel` uses native PlayCanvas world-space Screen/Element components, Texture, and ElementInput. It installs an XR-only ElementInput manager when the React application has none, and releases it on exit. The pinned engine's `XrInputSource.elementEntity` declaration says Entity, while its ElementInput implementation returns ElementComponent; a single cast isolates that mismatch. No separate UI ray picker or `XrMenu` visibility adapter remains.

The UI texture is drawn with browser canvas fonts and shared vector icons. Colours and font family are read from the actual desktop CSS at construction. Tool definitions and measurement slider definitions are shared. Canvas buffers are reused, textures resize through the engine API when the form grows/collapses, and uploads happen on edits and hover changes, not every frame. The spatial keyboard is allocated for the session and shown only for text input. Review these adapters on engine upgrades.

Desktop and XR measurement preview/clicks use the same surface-ray adapter. Meshes reuse the existing `three-mesh-bvh` selection worker and its public `raycastFirst`/`raycast` functions, without another BVH or a picking camera. Segment/isolation masks transfer only after edits; transforms, side policy, and the retained section plane accompany each small ray query. Splat queries use resident centers within the same scope and remain estimated surface locations. Preview sampling is movement-driven with at most one query in flight (XR capped at 60 Hz), and no idle readback/render pass. Hits convert with the inverse asset transform captured at query time, so movement during worker latency does not misplace the stored anchor.

`SurfacePointMarker` supplies the same live white surface sphere on desktop and XR; the shared MeasurementRenderer supplies endpoints, labels and the stereo line. Measurement style is cached before immersive entry: querying inherited CSS on the immersive canvas produced NaN sphere sizes and label offsets. Desktop mouse pickers/gizmos are suspended in XR while shared scene visuals continue rendering. Measurement layers created during XR reattach after desktop camera restoration.

Browser integration tests drive real IWER controller events and check Navigate entry, icon activation, name entry, saved records, sliders, collapse, endpoint dragging, navigation, section coexistence, desktop sharing, and teardown on meshes and splats. A generated plane with known coordinates checks preview/click correspondence, transformed endpoint/line placement, visible endpoint pixels, and absence of extra scene-camera frames. Screenshots include the stereo result and the form texture. Development and minified production builds both require checks. Actual Quest comfort, text legibility, hit targets, and performance still require headset validation; emulator success does not establish those properties.

## Selection and annotations

Selection uses the same masks, `SelectionHistory`, saved areas, paint palette/hex colors, Remove Color and Isolate operations as desktop. Hold the right trigger and trace a box, lasso or brush stroke. A fixed controller-view camera and a plane anchored at the initial surface depth define the stroke projection independently of head movement; PlayCanvas camera math and the shared Canvas rasterizer map it into the existing GPU/BVH selection pipeline. Strokes add to the draft, and Save consolidates them; Navigate clears unsaved selection work and paint. Left-trigger orbit, thumbstick zoom and grip manipulation remain available. The right trigger draws rather than pans in Selection. Native query cameras remain disabled; layer membership is scoped to the synchronous pick pass and restored before asynchronous readback. WebGL CPU-sorted splats replay the resident headset splat mesh through the native depth pass, without a second sorter or geometry copy. This pinned-engine adapter is needed because native `prepareForPicking` handles GPU sorting only; review it on upgrades.

Annotation uses the same `Annotations` document and selection snapshots. Choose point or selection annotation, hover/click a selection, place the marker, enter Title and Description, and Save. Saved notes reopen for editing/removal; a marker can be dragged after opening it or choosing its saved-row Move action, then saved. Cancel and tool exit discard the draft. The existing PlayCanvas annotation scene markers are initialized before XR, and a native spatial description panel presents the note when its marker/region is targeted; no DOM tooltip is required inside the headset. Painted selections retain their color and scope. Saved records remain available on desktop after exit.

Controller rays end at the nearest asset/UI target. Surface results (including stable primitive IDs) are shared with the white measurement/annotation preview and region hover; mesh queries reuse the existing BVH worker, and splats use their resident-center query. There is at most one background query in flight per controller, movement/transform/edit invalidation drives sampling, and no queries run at idle. UI clipping uses the native ElementInput target plane. Panel textures redraw on edits and hover transitions; gold border/glow feedback covers buttons, fields, sliders, keyboard keys and collapse controls. Desktop uses the same gold hover/focus styling without layout movement. Native Screen priority ensures the keyboard receives input above the options behind it.

## Remaining slices

1. **Menu and measurement:** Implemented and browser-tested as described above. Quest device validation remains; the spatial name keyboard and style controls are implemented.
2. **Annotations:** Point/region placement, text entry, Save, reopen, marker move and spatial descriptions are implemented; Quest validation remains.
3. **Selection, paint, and segments:** Controller-view box/lasso/brush, visible-only/X-ray, saved selections, paint and annotation binding are implemented. Entering/creating segment workspaces from XR remains deferred.
4. **Views and sections:** Let controller handles rotate the asset relative to the fixed world axes, then save/recall through the existing view records. Expose cutting-plane normal, offset, tilts, flip, and Save through the same section state. Keep the plane and annotations in the shared scene and section picks on retained surfaces.
5. **Capture and remaining document actions:** Define a dedicated XR spectator capture rather than assuming the desktop canvas contains both eyes in a usable PNG. Expose saved-item open, rename, visibility, delete, undo/redo, isolation, and return-to-asset in the menu. Decide whether four-view remains a desktop layout rather than simulating four windows in a headset.

For each slice, run a real browser session with Meta IWER against development and minified production builds for both asset formats, plus a Quest 3 check for interaction comfort, text legibility, controller hit targets, stereo visuals, and performance. Compose each tool with sectioning, segment workspaces, existing saved records, XR manipulation, and session exit/re-entry. Benchmark render time and memory before adding a continuous controller preview or another pick pass. Emulator success does not establish headset usability.
