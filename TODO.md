# Viewer roadmap

## Deferred

- LOD device coverage: verify Safari/WebGPU and actual immersive sessions, including source/work-buffer stream limits, stereo consistency, controller picking and large-asset memory. Desktop three-level streaming and shared edit projections are implemented in [docs/lod.md](docs/lod.md). Evaluate mesh texture sharing/cache eviction only where profiling justifies it; seamless geometry morphing is not implemented.

- AWS processing migration: macOS processing is temporary; the complete mesh/splat derivative and thumbnail pipeline is intended to move to AWS. The new RPly helper has only been executed on macOS. Before switching, provision the Linux C/C++ toolchain, Python/NumPy/SciPy correspondence dependencies and processing dependencies, verify a clean native build and recovery fidelity, exercise the complete batch-to-publication workflow, and benchmark memory/disk/compute and SOG k-means on the target instance. Track acceptance checks in the [backend migration gap](https://github.com/desaibhargav/mesh-splat-artifact-service#open-gap-move-processing-back-to-aws). Existing AWS asset serving does not establish processing compatibility.
- Relighting: add non-destructive lighting/environment controls with neutral defaults and reset. Reuse PlayCanvas scene lighting for meshes; evaluate what is supported for captured Gaussian-splat appearance before promising physical relighting. Share controls/operations where meaningful, account for XR, and test alongside selection, colors, annotation, sectioning, and four-view layouts. Planned for a future session.
- Color enhancement: add non-destructive exposure, contrast, saturation, and white-balance controls, with a clear original-appearance reset. Reuse engine capabilities, keep mesh/splat and future XR workflows consistent, and verify composition with selection paint, lighting, sectioning, and annotations. Planned for a future session.

- Saved views: use IndexedDB for named, browser-local views containing asset ID and derivative revision, camera pose/orbit pivot, bit-packed selection and isolation, measurement endpoints, persistent selection colors, and annotation text/anchors/regions. Save edits rather than frames, load only the current asset, and do not duplicate model bytes. Add export/import of view data, record validation, plain-text rendering, and clear local-only storage messaging. Account for storage eviction, private browsing, shared browser profiles, and origin changes; avoid storing credentials or private source paths. Cross-device sharing would be separate authenticated backend work.
- WebXR VR/AR: feasible with PlayCanvas XR APIs; first add capability-gated immersive viewing on a stable HTTPS origin, with explicit session start/end and AR placement/scale controls. Then adapt saved asset orientations/three-point alignment, sectioning, selection/isolation, measurement, and annotations for controller/hand input and world-space UI using the same tool operations. Measurement visuals already share PlayCanvas cylinder lines, sphere markers, and text elements on desktop and stereo cameras. Add XR-visible controls around the same tool operations; there must be no separate mesh/splat or desktop/XR measurement implementation. Annotation tooltip text also needs XR presentation. Reuse tool state and operations, add XR-specific interactions, and test mesh/splat rendering and stereo performance on target devices. AR and input capabilities vary by browser/headset; physical measurements still require calibrated units. References: [PlayCanvas WebXR](https://developer.playcanvas.com/user-manual/xr/using-webxr/), [XR platforms](https://developer.playcanvas.com/user-manual/xr/platforms/).
- Measurement: per-asset units or known-distance calibration and measurement types beyond straight-line distance. Current implementation: [docs/measurement.md](docs/measurement.md).
- Selection accuracy: improve missed triangles in visible-only GPU picking, especially on dense meshes at distant zoom. Compare coverage approaches without reintroducing CPU ray casting.
- Thumbnails: improve automatic framing, view choice, and consistent neutral lighting.
- Turntable previews: generate discrete views for an interactive catalog preview; revisit thumbnail rendering as part of this work.
- Sectioning: the shared clipping plane, offset, two tilts, flip, saved-reference selection, and scene guide are implemented in [docs/sectioning.md](docs/sectioning.md). Filled caps and intersection contours remain deferred; evaluate established geometry libraries before implementation.
- Saved views/sections and four-view inspection: named cuts are available in the model tree; the viewer-wide Top/Front/Right/Perspective workspace shares all tools and uses Space to maximize/restore a panel. See [workspace](docs/viewports.md). Session-local asset orientation with a native rotation gizmo, fixed world grid, native world-viewpoint widget, orthographic inspection, and three-point alignment are implemented in [docs/views.md](docs/views.md) and feed sectioning. Persistent full-document views remain the separate IndexedDB item above; face alignment is omitted for the shared mesh/splat workflow.
- Appearance controls, including tint and opacity.
