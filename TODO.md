# Viewer roadmap

## Deferred

- Energy/idle rendering: selection picking and BVH queries are edit-time only, but the existing viewer still continuously renders its scene. Add native `autoRender` / `renderNextFrame` policy with explicit invalidation for camera damping, asynchronous edits/assets, gizmos, hover, resizing and all shared tools. Suspend unnecessary offscreen work, retain XR's session rendering requirements, and profile Safari energy/CPU/GPU/memory alongside Chromium before claiming battery improvements. Test both formats, four views, all edit workflows and navigation cleanup; avoid idle timers or frame caps that leave stale visuals.
- AWS processing migration: macOS processing is temporary; the complete mesh/splat derivative and thumbnail pipeline is intended to move to AWS. The new RPly helper has only been executed on macOS. Before switching, provision the Linux C/C++ toolchain and processing dependencies, verify a clean native build and recovery fidelity, exercise the complete batch-to-publication workflow, and benchmark memory/disk/compute and SOG k-means on the target instance. Track acceptance checks in the [backend migration gap](https://github.com/desaibhargav/mesh-splat-artifact-service#open-gap-move-processing-back-to-aws). Existing AWS asset serving does not establish processing compatibility.
- Relighting: add non-destructive lighting/environment controls with neutral defaults and reset. Reuse PlayCanvas scene lighting for meshes; evaluate what is supported for captured Gaussian-splat appearance before promising physical relighting. Share controls/operations where meaningful, account for XR, and test alongside selection, colors, annotation, sectioning, and four-view layouts. Planned for a future session.
- Color enhancement: add non-destructive exposure, contrast, saturation, and white-balance controls, with a clear original-appearance reset. Reuse engine capabilities, keep mesh/splat and future XR workflows consistent, and verify composition with selection paint, lighting, sectioning, and annotations. Planned for a future session.
- Point-SAM segmentation: promising for prompt-driven segment creation, but the official ICLR 2025 implementation is currently a Python/PyTorch/CUDA backend rather than a browser model. Its ViT-L checkpoint is about 1.24 GB; preprocessing uses farthest-point sampling and KNN, and the official mesh demo samples points then propagates masks back to faces. Do not ship that checkpoint or a speculative ONNX port in the portal. First benchmark a private AWS GPU proof of concept against representative meshes and splats, including upload/privacy boundaries, point sampling, primitive-label propagation, latency, memory, mask quality, and segment-tool composition. Re-evaluate a browser path only if a supported smaller checkpoint and verified ONNX/WebGPU export become available; run inference in a worker and preserve the shared segment operation. References: [official repository](https://github.com/zyc00/Point-SAM), [paper/project](https://point-sam.github.io/), and [official checkpoint](https://huggingface.co/yuchen0187/Point-SAM/tree/main).

- Saved views: use IndexedDB for named, browser-local views containing asset ID and derivative revision, camera pose/orbit pivot, bit-packed selection and isolation, measurement endpoints, persistent selection colors, and annotation text/anchors/regions. Save edits rather than frames, load only the current asset, and do not duplicate model bytes. Add export/import of view data, record validation, plain-text rendering, and clear local-only storage messaging. Account for storage eviction, private browsing, shared browser profiles, and origin changes; avoid storing credentials or private source paths. Cross-device sharing would be separate authenticated backend work.
- WebXR VR/AR: capability-gated immersive viewing is implemented with native PlayCanvas sessions, one-time bounds-based placement, AR transparency, and desktop/four-view restoration. Meta IWER checks cover both formats in development and production; real Quest 3 validation is pending. See [XR](docs/xr.md). Next add controller/hand manipulation, placement/scale controls, and world-space tool UI around existing shared operations. Adapt saved orientations/three-point alignment, sectioning, selection/isolation, measurement, annotations, and segments without separate desktop/XR or mesh/splat implementations. Verify measurement labels, annotation presentation, stereo performance, permissions, and room capabilities on target devices. Surface placement, room occlusion and persistent anchors remain separate work; physical measurements still require calibrated units.
- Measurement: per-asset units or known-distance calibration and measurement types beyond straight-line distance. Current implementation: [docs/measurement.md](docs/measurement.md).
- Selection accuracy: cropped native GPU picking plus a worker-based `three-mesh-bvh` centroid-visible supplement covers the recorded 1M-mesh brush misses and the dense-grid/occluded-plane regression. Retain investigation of faces with occluded centers and arbitrarily subpixel visible slivers, numerical edge cases, and splat visibility. Evaluate an explicit, undoable **Grow selection** operation as a separate tool action: one bounded adjacency ring per press, constrained by the committed view/visibility so it cannot silently cross silhouettes, gaps, clipped surfaces, or the back side. Reuse an established adjacency/spatial-index implementation after benchmarking construction, memory and edit latency. Mesh topology and splat spatial neighborhoods need narrow format adapters behind one documented operation; do not ship raw screen-space dilation or pretend those neighborhoods are identical. Keep real-asset coverage, hidden-face rejection, performance and cross-tool tests; see [viewer tools](docs/viewer-tools.md). Do not blindly select hidden neighbours, promise universal coverage, or copy GPL Blender implementation code without license review. Reference: [Blender selection engine](https://github.com/blender/blender/blob/main/source/blender/draw/engines/select/select_engine.cc).
- Segments: shared geometry and independent tool documents are implemented; see [segments](docs/segments.md). Persistent storage and immersive input/UI remain covered by their separate items below. Seed growing and area/volume calculations are explicitly out of scope for this version.
- LOD experiment: archived on the `lod` branch in both repositories; all generated LOD bundles remain private on the Mac. Main intentionally serves one 30% derivative per asset with the existing mesh triangle cap.
- Thumbnails: improve automatic framing, view choice, and consistent neutral lighting.
- Turntable previews: generate discrete views for an interactive catalog preview; revisit thumbnail rendering as part of this work.
- Sectioning: the shared clipping plane, offset, two tilts, flip, saved-reference selection, and scene guide are implemented in [docs/sectioning.md](docs/sectioning.md). Filled caps and intersection contours remain deferred; evaluate established geometry libraries before implementation.
- Saved views/sections and four-view inspection: named cuts are available in the model tree; the viewer-wide Top/Front/Right/Perspective workspace shares all tools and uses Space to maximize/restore a panel. See [workspace](docs/viewports.md). Session-local asset orientation with a native rotation gizmo, fixed world grid, native world-viewpoint widget, orthographic inspection, and three-point alignment are implemented in [docs/views.md](docs/views.md) and feed sectioning. Persistent full-document views remain the separate IndexedDB item above; face alignment is omitted for the shared mesh/splat workflow.
- Appearance controls, including tint and opacity.
